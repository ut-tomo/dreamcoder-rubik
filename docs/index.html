About

DreamCoder learns to solve tasks by writing programs in a small language (a DSL). It alternates three phases: wake searches for programs that solve the tasks; abstraction finds sub-programs that keep recurring in the solutions and adds them to the DSL as new routines; dreaming trains a neural recognition network that looks at a task and predicts which building blocks the next search should try first.

Here the tasks are stages of solving a 2×2×2 cube. We switch the two learning mechanisms on and off, giving four arms:

  • NN + library: full DreamCoder.
  • NN only: recognition network, but the DSL never grows.
  • Library only: the DSL grows, and search uses one learned distribution for every task.
  • Neither: plain best-first enumeration over the base primitives.

Moves use Singmaster notation: R turns the right face clockwise, R' turns it counterclockwise, R2 is a half turn. Colours: up white, down yellow, front green, back blue, right red, left orange.

Watch Them Solve

Four versions of the system, trained on the same tasks with the same compute. Pick a task: all four cubes start from the same state and play the solution each version found, one move at a time. Held-out tasks were never seen during training.

What Each Arm Learned

The search policy is the probability each arm gives to every building block when it starts writing a program (top 12 shown, averaged over the tasks of a stage). The plain-search arms use one distribution for every task. The NN arms' recognition network predicts a different distribution from each task's cube state and goal. The library-learning arms can also pick their own invented routines (#(…)).

Learned library

#(…) is a learned routine and $0 is its argument. comm a b = a b a⁻¹ b⁻¹, setup a b = a b a⁻¹, and x y z mirror apply the same alg from another side or mirrored.

    Setup

    • Programs have a single type, alg: a move sequence treated as a permutation of the 24 stickers. Running a program applies it to the task's start state.
    • Primitives: face turns R U F, the combinators seq inv setup comm, and the whole-cube symmetries x y z mirror (48 symmetries in total). No colours, pieces or human solving methods are built in.
    • Invariance: states are compared up to how the whole cube is held. Before a goal is checked, the cube is turned so the DLB corner is home.
    • Stages (chained subgoals): 1 DRF corner → 2 + DRB corner → 3 whole D layer → 4 + U face one colour → 5 solved. Each stage starts from a random state where the earlier stages are already done. 24 tasks per stage.
    • Recognition network (NN arms): an MLP (2 hidden layers of 128, ReLU). The input is the colour of each of the 24 sticker slots (one-hot) plus the stage id. The output is one log-weight per DSL entry, giving a task-specific unigram grammar (as in the paper's unigram model). It is trained after every round for 800 Adam steps on replays (solved training tasks and their programs) and 2000 fantasies: a program is sampled from the current DSL, a goal-satisfying end state G is drawn, and the task starts from G·p⁻¹, so the program is known to solve it. Loss: −log P(program | predicted grammar).
    • Compute matching: NN arms enumerate separately for each task (1 s per task, under that task's predicted grammar). Plain arms enumerate once for all tasks together, for 1 s × number of tasks. Round 1 of the NN arms uses plain search, because no network is trained yet.
    • Settings: 8 rounds, best 3 programs kept per task, at most 3 new routines per round, structure penalty 1.0. Training: 120 tasks (24 per stage). Held-out: 60 fresh tasks (12 per stage). Seeds 0 and 1.
