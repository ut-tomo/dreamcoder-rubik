Setup

The idea in one paragraph

Instead of training a network that outputs moves, DreamCoder writes small programs that turn a scrambled cube into a goal state. It repeats three phases for 20 rounds:

  1. Wake (search): for each training task, try programs from most to least likely under the current "grammar" (a probability for each building block), until one reaches the goal or the time budget runs out.
  2. Abstraction (library learning): look at all solutions found so far, find sub-programs that keep recurring, and add them to the language as new named routines (shown as #(…)). Later searches can then use a whole routine as one step, so long solutions become short programs.
  3. Dreaming (neural guidance): train a recognition network that looks at a cube and predicts which building blocks are likely to be useful, so the next search tries them first.

Search can only learn from tasks it actually solves. If nothing is solved, there is nothing to compress into routines and no real examples to train the network on. This is why the choice of training tasks matters so much below.

The four arms

We switch abstraction and neural guidance on and off independently:

  • NN + library: full DreamCoder.
  • NN only: the network guides search, but the language never gains new routines.
  • Library only: the language grows, but every task is searched with the same learned probabilities.
  • Neither: plain enumeration over the base building blocks, which is a brute-force baseline.

Two training strategies

  • Full task only: 120 random scrambled cubes, each with the goal "solved". The model has to discover a whole solution at once.
  • Subtask curriculum ("stages"): solving is split into five chained subgoals, roughly how a beginner solves the cube:
    1. place one bottom corner (DRF),
    2. place a second bottom corner (DRB),
    3. complete the whole bottom layer,
    4. make the top face one colour,
    5. solve the cube.
    Each stage's training tasks start from a random state in which the earlier stages are already done. There are 24 tasks per stage (stage 5 has only 23 possible starts), 119 tasks in total. Only the subgoal definitions are given. The model is not told how to reach them.

How we test

Every run is evaluated on the same 100 random scrambled cubes, none of which appear in any training set. A cube counts as solved only if it ends fully solved. In the stage strategy, the learned solvers are chained: stage 1's program runs, then stage 2's program runs on the result, and so on. If any stage fails, the cube fails. We report how many of the 100 cubes are solved and the average solution length in face turns. Each configuration is trained with 3 seeds (0, 1, 2).

The cube language (DSL)

Moves use standard notation: R turns the right face clockwise, R' counterclockwise, R2 a half turn.

  • A program is a move sequence. Running it applies it to the task's starting cube.
  • Building blocks: the face turns R U F, plus four ways to combine sequences: seq a b (do a, then b), inv a (undo a), setup a b = a b a⁻¹, and comm a b = a b a⁻¹ b⁻¹ (the commutator, a classic cube-solving tool). x y z mirror apply a sequence from another side, or mirrored.
  • No piece names, colours or human algorithms are built in.
  • Goals are checked regardless of how the whole cube is held. Before each check, the cube is rotated so its back-left-bottom corner is in place. A 2×2×2 has no centre pieces, so this corner fixes the orientation.

Model and hyperparameters

  • Recognition network (NN arms): an MLP with 2 hidden layers of 128 units (ReLU). Input: the colour of each of the 24 stickers (one-hot) plus the stage id. Output: one weight per building block, giving a probability for each block that depends on the cube in front of it. After every round it is trained for 800 Adam steps on solved tasks plus 2000 "dreams": a random program is sampled from the current language and run backwards from a goal state, which gives a task whose solution is known.
  • Search budget: 5 s per task (NN arms search each task separately; the other arms search all tasks together with the same total time). At test time: 5 s per stage, or 25 s per cube for the full strategy.
  • Library: at most 3 new routines per round, best 3 programs kept per task, structure penalty 1.0.
  • Implementation: a pure-Python reimplementation of DreamCoder (unigram grammar, simplified compression), checked against the official OCaml code on its list-processing benchmark. It is not the official engine.

Results

All 24 runs complete (including the 15 relaunched runs), checked 8 November 2026. Each has 20 training rounds and a final end-to-end evaluation. Counts below are complete solves of the same 100 unseen random cubes, not independent stage successes.

Stages + library: 100/100 in all six runs. Without a library, NN-only solves 16/18/25 and neither solves 17/17/17. Full-task training solves 0/100 in every NN run and 1/100 in every plain-search run. Library learning helps strongly with the staged curriculum, but does not bootstrap full random-cube solving here. Neural guidance has no consistent solve-rate advantage at this budget; all full-task arms solved zero training tasks; NN training therefore relied on fantasies, with no successful task replays.

Average moves counts only solved cubes; “–” means no solutions. Long expanded solutions are not speedcubing algorithms. Seeds reuse the same test cubes and are not independent test samples. Use the run selector below to change the training curve, stage-survival chart, policies and playback.

What Each Arm Learned

The search policy is the probability each arm gives to every building block when it starts writing a program (top 12 shown, averaged over the tasks of a stage). The plain-search arms use one distribution for every task. The NN arms' recognition network predicts a different distribution from each task's cube state and goal. The library-learning arms can also pick their own invented routines (#(…)).

Learned library

#(…) is a learned routine and $0 is its argument. comm a b = a b a⁻¹ b⁻¹, setup a b = a b a⁻¹, and x y z mirror apply the same alg from another side or mirrored.
