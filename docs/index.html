Setup

DreamCoder-style learning alternates program search (wake), symbolic MDL library compression (abstraction), and neural training on solved tasks and synthetic fantasies (dreaming). We compare staged and full-cube training on the 2×2×2. We switch the two learning mechanisms on and off, giving four arms:

  • NN + library: both learning mechanisms.
  • NN only: recognition network, but the DSL never grows.
  • Library only: the DSL grows, and search uses one learned distribution for every task.
  • Neither: plain best-first enumeration over the base primitives.

Moves use Singmaster notation: R turns the right face clockwise, R' turns it counterclockwise, R2 is a half turn.

  • Programs have a single type, alg: a move sequence treated as a permutation of the 24 stickers. Running a program applies it to the task's start state.
  • Primitives: face turns R U F, the combinators seq inv setup comm, and the whole-cube symmetries x y z mirror (48 symmetries in total). No colours, pieces or human solving methods are built in.
  • Invariance: states are compared up to how the whole cube is held. Before a goal is checked, the cube is turned so the DLB corner is home.
  • Stages (chained subgoals): 1 DRF corner → 2 + DRB corner → 3 whole D layer → 4 + U face one colour → 5 solved. Each stage starts from a random state where the earlier stages are already done. 24 distinct tasks per stage, except stage 5 (23 possible unsolved starts).
  • Recognition network (NN arms): an MLP (2 hidden layers of 128, ReLU). The input is the colour of each of the 24 sticker slots (one-hot) plus the stage id. The output is one log-weight per DSL entry, giving a task-specific unigram grammar (as in the paper's unigram model). It is trained after every round for 800 Adam steps on replays (solved training tasks and their programs) and 2000 fantasies: a program is sampled from the current DSL, a goal-satisfying end state G is drawn, and the task starts from G·p⁻¹, so the program is known to solve it. Loss: −log P(program | predicted grammar).
  • Compute matching: NN arms enumerate separately for each task (5 s per task, under that task's predicted grammar). Plain arms enumerate once for all tasks together, for 5 s × number of tasks. Round 1 of the NN arms uses plain search, because no network is trained yet.
  • Settings: 20 rounds, best 3 programs kept per task, at most 3 new routines per round, structure penalty 1.0. Stages: 119 training tasks; full-task strategy: 120 uniformly random training cubes. Test: the same 100 distinct random cubes (seed 9999), excluded from all training sets. Three training seeds: 0, 1, 2.

Two training strategies: stages learns five chained subgoals; full learns only random-cube → solved. End-to-end evaluation chains stage solvers, reorienting after each stage, or searches once for a full solution. NN search receives up to 5 s per stage or 25 s per full cube. Plain search pools that budget across the batch; these are aggregate wall-time budgets, not equal enumeration counts or total training costs.

This is a pure-Python DreamCoder-style reimplementation, not the official engine: unigram grammar/recognition and simplified MDL compression. No human algorithm library is provided. Search order is learned; expanded move count is not the objective.

Results

All 24 runs complete (including the 15 relaunched runs), checked 8 November 2026. Each has 20 training rounds and a final end-to-end evaluation. Counts below are complete solves of the same 100 unseen random cubes, not independent stage successes.

Stages + library: 100/100 in all six runs. Without a library, NN-only solves 16/18/25 and neither solves 17/17/17. Full-task training solves 0/100 in every NN run and 1/100 in every plain-search run. Library learning helps strongly with the staged curriculum, but does not bootstrap full random-cube solving here. Neural guidance has no consistent solve-rate advantage at this budget; all full-task arms solved zero training tasks; NN training therefore relied on fantasies, with no successful task replays.

Average moves counts only solved cubes; “–” means no solutions. Long expanded solutions are not speedcubing algorithms. Seeds reuse the same test cubes and are not independent test samples. Use the run selector below to change the training curve, stage-survival chart, policies and playback.

Watch Them Solve

Select a strategy and seed, then a held-out random cube or training task. All four arms start from the same state. A missing solution means no complete solution was recorded, not that the cube is impossible. Stage solutions reorient the cube between subprograms, exactly as evaluation does. Every exported move sequence is replay-verified against its goal.

Drag a cube to look around. At stage boundaries and the end, the whole cube turns so the back-left-bottom corner is home (goals are checked up to orientation).

What Each Arm Learned

The search policy is the probability each arm gives to every building block when it starts writing a program (top 12 shown, averaged over the tasks of a stage). The plain-search arms use one distribution for every task. The NN arms' recognition network predicts a different distribution from each task's cube state and goal. The library-learning arms can also pick their own invented routines (#(…)).

Learned library

#(…) is a learned routine and $0 is its argument. comm a b = a b a⁻¹ b⁻¹, setup a b = a b a⁻¹, and x y z mirror apply the same alg from another side or mirrored.
